# Upgrading

## Latest Stable version

To update to the latest version of Rasengan.js, you just have to run the following command:

```bash title="Terminal"
pnpm add rasengan@latest
```

## Latest Beta version

To update to the latest `beta` version of Rasengan.js, you just have to run the following command:

```bash title="Terminal"
pnpm add rasengan@beta
```

## Upgrade from 1.x to 2.0

**Version `2.0.0`** rewrites Rasengan.js's entire server layer on top of <Link to="/docs/futon/getting-started/introduction">Futon</Link>, a lightweight WinterCG-compatible HTTP engine, replacing Express everywhere: the dev server, production request handling, and every deployment adapter. Read the <Link to="/blog/rasengan-2-stable">2.0 announcement</Link> for the full picture.

### What changed

- **Express is gone.** `rasengan/server` no longer exports `express`/`compression`. If you were adding custom Express middleware to your app's server, it needs to move to a Futon `Middleware` instead. See the <Link to="/docs/futon/middleware">Futon Middleware</Link> guide.
- **New peer dependency versions required**: `vite@^8.0.0`, `react-router@^8.3.0`, `react`/`react-dom@^19.2.7`.
- **`react-router` must now be installed directly in your own project.** It moved from a `rasengan` dependency to a `peerDependency`, so your SSR build resolves the same `react-router` instance rasengan's own server code does. Skipping this makes the build succeed but renders an empty page in production (nested routes never show up, even though nothing errors): `react-router` would otherwise get bundled a second time inside your app's own SSR chunks, with its own, separate route context that never receives the data the real one provides.
- **`detectRuntime()` was renamed to `detectDeploymentPlatform()`.** Only relevant if you imported it directly from `rasengan/server`; the name `detectRuntime` moved to `@rasenganjs/runtime`'s own, unrelated export.
- **New `runtime` config option** (`'node' | 'bun' | 'workerd'`) lets `@rasenganjs/serve` run your production build on <Link to="/packages/serve">Bun instead of Node.js</Link>. Defaults to `'node'`, so existing apps don't need to change anything.
- **New file-based <Link to="/docs/routing/api-routes">API routes</Link>** (`src/app/_api/`), a way to build server-only HTTP endpoints without a full page, entirely optional and additive.
- **`@rasenganjs/netlify` now works.** The adapter had been broken since before this rewrite; it's rebuilt on Futon along with `@rasenganjs/vercel`. See <Link to="/docs/deploying/netlify">Deploying to Netlify</Link>.

### Upgrade steps

<StepItem
  step="01"
  title="Update your dependencies"
  content={`
    Bump Rasengan.js and its peer dependencies to the versions this release requires.
  `}
  className="mt-8"
>
```bash title="Terminal"
pnpm add rasengan@latest react@latest react-dom@latest vite@latest
```
</StepItem>

<StepItem
  step="02"
  title="Add react-router as a direct dependency"
  content={`
    This step is required for every app, not just ones with a custom server. react-router needs to be resolvable from your own project, not only transitively through rasengan.
  `}
  className="mt-8"
>
```bash title="Terminal"
pnpm add react-router@^8.3.0
```
</StepItem>

<StepItem
  step="03"
  title="Remove any direct Express usage"
  content={`
    If your app doesn't customize the server at all (the vast majority of apps), you can skip this step entirely. If it does, replace any Express-specific middleware or request/response handling with Futon's equivalents.
  `}
  className="mt-8"
>
Before

```ts title="custom server code" /express/
import { express, compression } from 'rasengan/server';

app.use(compression());
app.use(express.static('public'));
```

After

```ts title="custom server code" /staticFiles|compress/
import { staticFiles, compress } from 'rasengan/server';

app.use(compress());
app.use(staticFiles({ root: 'public' }));
```
</StepItem>

<StepItem
  step="04"
  title="Rebuild and test your deployment"
  content={`
    Run a fresh build and verify your app still deploys correctly, especially if you're on Netlify (previously broken) or use a custom deployment integration.
  `}
  className="mt-8"
>
  ```bash title="Terminal" 
  pnpm run build 
  pnpm run serve
  ```

  If you have SSR enabled, check that a real route's HTML response has your actual page content inside `<div id="root">`, not only a hydration script. A clean build doesn't guarantee the production render is correct, that's exactly the failure mode step 02 prevents.
</StepItem>

## Upgrade from 1.1.x to 1.2.x

If you want to improve the performance of your application, especially as it grows in size, upgrading to **version `1.2.x`** is a great choice.

This version introduces several major features:

### New Error Boundary Overlay (since v1.2.2)

Rasengan v1.2.2 introduces a **completely redesigned error handling experience** with a developer-friendly overlay that catches errors from every source:

- **React rendering errors:** Caught by a class-based `ErrorBoundaryFallback` component wrapping your application tree
- **Route loader errors:** Every route is automatically wrapped with an error boundary that feeds into the overlay
- **Global unhandled errors and rejections:** `window.onerror` and `window.onunhandledrejection` are registered and captured
- **Vite HMR errors:** Errors during hot module replacement are displayed in the overlay
- **SSR errors:** Server-side rendering errors are serialized into `window.__RASENGAN_SSR_ERROR__` and forwarded to the client overlay after hydration

### Lazy Loaded Routes (since v1.2.0)

Routes are now loaded **on demand**, based on the page the user is visiting.
This means your app only loads what it needs, when it needs it, which helps reduce initial load time and makes navigation feel faster.

Everything is handled automatically, there is no option to opt out this feature.

### SSG (Static Site Generation) (since v1.2.0)

You can now generate **static HTML files** for your pages ahead of time.
This improves performance, SEO, and allows your site to be served extremely fast, without waiting for server responses or client-side rendering.

<br />

The configuration is simple, inside the `rasengan.config.js` file, you just have to enable the `prerender` option.

```js title="rasengan.config.js" {5}
import { defineConfig } from 'rasengan';
import { rasengan } from 'rasengan/plugin';

export default defineConfig({
  prerender: true,
  vite: {
    plugins: [rasengan()],
  },
});
```

This is the minimal configuration, it will enable the prerender globally into your application. If you prefer, you can select what you really want to prerender.

```js title="rasengan.config.js" {5-7}
import { defineConfig } from 'rasengan';
import { rasengan } from 'rasengan/plugin';

export default defineConfig({
  prerender: {
    routes: ['/', 'blog/**'],
  },
  vite: {
    plugins: [rasengan()],
  },
});
```

This approach is ideal for **hybrid applications**, where:

- Public pages are statically generated
- Authenticated or dynamic routes remain rendered via SSR or SPA

<br />
So, to upgrade you have to follow the following steps:

<StepItem
  step="01"
  title="Install the target dependency"
  content={`
    Run the following command to install the correct version of Rasengan.js
  `}
  className="mt-8"
>
  ```bash title="Terminal" 
  pnpm add rasengan@~1.2.2 
  ```
</StepItem>

<StepItem
  step="02"
  title="Remove AppRouter from main.tsx file"
  content={`
    Get off the AppRouter instance from the main.tsx, because it's not longer important there.
  `}
  className='mt-8'
>
Before
```tsx title="main.tsx" {3} /AppRouter/
import '@/styles/index.css';
import { type AppProps } from 'rasengan';
import AppRouter from '@/app/app.router';

export default function App({ Component, children }: AppProps) {
  return <Component router={AppRouter}>{children}</Component>;
}
```

After

```tsx title="main.tsx"
import '@/styles/index.css';
import { type AppProps } from 'rasengan';

export default function App({ Component, children }: AppProps) {
  return <Component>{children}</Component>;
}
```

</StepItem>

<StepItem
  step="03"
  title="Move the AppRouter to the index.ts file"
  content={`
    Now import the AppRouter instance into the index.ts file
  `}
  className='mt-8'
>
Before
```ts title="index.ts"
import { renderApp } from 'rasengan/client';
import App from './main';

renderApp(App, { reactStrictMode: true });

````

After
```ts title="index.ts" {3} /AppRouter/
import { renderApp } from 'rasengan/client';
import App from './main';
import AppRouter from '@/app/app.router';

renderApp(App, AppRouter, { reactStrictMode: true });
````

</StepItem>

<StepItem
  step="04"
  title="Start the dev server"
  content={`
    Then run the dev command to start the local server
  `}
  className="mt-8"
>
  ```bash title="Terminal" 
  pnpm run dev 
  ```
</StepItem>
